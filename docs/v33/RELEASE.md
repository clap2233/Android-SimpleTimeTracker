# V3.3：未完成专注

版本 `1.59-life-clock-v3.3`（166），数据库 40，完整快照 schema 4。沿用正式包名和既有签名，覆盖 V3.2 升级，无需卸载。日期：2026-10-18。

## 使用变化

- 专注类活动单次不足 15 分钟停止或切换时，保存为「未完成专注」，不直接舍弃。回顾单独列出次数、真实起止、中断时长及可选原因。
- 原因可稍后补充、修改或清除，不增加退出时必填项；原摘要、备注、评分、人物、环境和照片保留，可直接打开详情。
- 满 15 分钟后保留真实时长，22 分钟仍记 22 分钟。原专注退出轻提醒、普通自由计时和娱乐周期收尾提醒继续使用；未恢复确认时间／待整理流程。
- 正式时长、类别、评分分布、恢复感、重要模板、尝试比较和计划实际时长排除未完成项；其真实区间继续参与冲突校验，不计为未记录空白。
- 原计划关联保留，不自动将计划标为完成。混合正式与未完成经历不能合并；拆分未完成项不会转为正式经历，原因跟随用户选择的附件归属。
- 历史短记录和手工补记保持原样。修改活动／模板策略仅影响下次新计时；本次门槛以真实启动时刻判断，编辑起点不绕过或重置。

## 数据与兼容

新增独立的 `isUnfinishedFocus` 与可空 `unfinishedReason`，未使用旧 `reviewState` 表示未完成。数据库增量迁移 39→40，历史默认 false／null，不改写既有时间和评分。

完整 JSON＋照片 ZIP 保留全部新数据。旧 schema 1–3 可读，新增字段缺失时按原行为处理；恢复运行专注仍只截止备份时刻，不补计之后空档，未满 15 分钟的恢复区间保留为未完成专注。服务器先兼容 schema 1–4，再交付新版手机。

完整导出中的 CSV 增加明确状态、标记及原因，ICS 标题带「未完成专注」并标记为透明时段。旧格式 CSV／ICS／`.backup` 无法完整表达新记录，排除未完成项及对应旧备份标签关联；完整恢复请使用 ZIP。

电脑网页只读展示未完成模块与原因。AI 记录查询保留真实文本、评分和计划关联，正式统计单列未完成次数和耗时，不把原因缺失解释成没有中断。Context `2026-10-18-v3.3`，仅更新已确认产品原则，原笔记未改写。
